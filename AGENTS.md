# AGENTS.md — правила работы в репозитории «Маяк»

Этот файл читает ИИ-агент (Claude Code и подобные) перед каждой задачей. Люди тоже могут его читать: здесь описано, как мы работаем.

## Что это за проект

«Маяк» — открытая карта сетевой доступности. Агент (`mayak`) измеряет, что именно мешает открыться сервису (DNS, IP, SNI, QUIC), и по желанию пользователя отправляет обезличенный отчёт. Сервер (`mayakd`) агрегирует отчёты по паре «оператор (ASN) × сервис» и показывает статус. Проект только измеряет, обходом блокировок не занимается.

Источники правды, читать в таком порядке:

1. `docs/SPEC.md` — ТЗ (разделы 1–20; при расхождении приоритет у большего номера раздела).
2. `docs/adr/` — принятые решения: ADR-000 (свой движок), ADR-004 (модель угроз), ADR-005 (схема отправки).
3. Этот файл.

Если задача противоречит ТЗ или ADR, остановись и спроси, а не выбирай сам.

## Стек

- Go последней стабильной версии, зафиксировать в `go.mod`. Один модуль.
- Зависимости минимальные. Перед добавлением новой напиши, зачем она нужна и чем не подходит стандартная библиотека.
- Разрешено сразу: `spf13/cobra` (CLI), `go-chi/chi` (HTTP), `jackc/pgx` (Postgres), `miekg/dns`, `quic-go` (для QUIC-теста позже).
- Тесты: стандартный `testing`, таблицы и golden-файлы в `testdata/`.
- Rust, OHTTP и анонимные учётные данные пока **не трогаем** (ADR-005: это M7 и позже).

Создавай каталоги по мере надобности, не заранее.

## Жёсткие правила (нарушать нельзя)

**Приватность.**
- Никогда не логируй и не сохраняй IP-адрес клиента: ни `RemoteAddr`, ни `X-Forwarded-For`, ни в тексте ошибок. Если нужен ASN или `src_bucket`, вычисляй в памяти и сразу отбрасывай IP.
- В отчёт попадают только поля схемы `mayak.report/1`. Неизвестные поля отбрасываются.
- Любое изменение пути приёма сопровождается тестом «IP не оседает»: тестовый клиент с известным IP, после запроса поиск этого IP по логам и базе. Если найден, тест падает.

**Безопасность и нагрузка.**
- Агент проверяет только цели из подписанного списка `targets.json`. Произвольные цели из аргументов не принимаются.
- Потолки из раздела 5 ТЗ: не более 4 одновременных проверок, пауза 200–800 мс между ними, таймаут 8 секунд на тест.
- Агент по умолчанию ничего не отправляет. Отправка только после явного согласия (`mayak consent grant`) и показа точного JSON.

**Криптография.**
- Своих криптографических схем не изобретай. Используй стандартную библиотеку (`crypto/ed25519`, `crypto/tls`) и проверенные пакеты.

**Границы этапов.**
- Делай только то, что просят в текущей задаче. Не добавляй функции «на будущее».
- Не реализуй OHTTP, анонимные учётные данные, KVAC, Rust-код, пока владелец не скажет явно.

## Порядок работы над задачей

1. Прочитай задачу и указанные разделы ТЗ. Если что-то неясно, задай до 3 вопросов, потом работай.
2. Сначала тест, потом код. Для классификатора сначала таблица «наблюдения → вердикт», для приёма сначала тест на валидатор.
3. Один вертикальный срез за раз. Маленькие изменения, которые можно прочитать целиком.
4. После правок запусти `make check` (см. ниже). Не говори «готово», пока он не зелёный.
5. В конце коротко напиши: что сделано, какие файлы затронуты, что не сделано, какие решения принял сам.
6. Не коммить без просьбы. Если просят коммит, сообщение на английском в повелительном наклонении (`Add report validator`).

## Команды

`Makefile` должен содержать:

```
make test    # go test ./...
make vet     # go vet ./...
make fmt     # gofmt -l . (список неотформатированных файлов, должен быть пуст)
make check   # fmt + vet + test
```

## Стиль кода

- Ошибки оборачиваем с контекстом: `fmt.Errorf("resolve %s: %w", host, err)`. Не проглатываем ошибки.
- Контекст (`context.Context`) первым аргументом во всём, что ходит в сеть. Таймауты задаются через контекст.
- Публичные функции с комментариями на английском; пояснения к нетривиальной логике (почему так) на русском допустимы.
- Никаких глобальных изменяемых переменных, кроме `main`.
- Вердикты и коды ошибок — константы, а не строки, разбросанные по коду.

## Что делать, когда не уверен

Остановись и спроси владельца. Особенно в этих случаях: изменение формата отчёта, добавление зависимости, всё, что трогает приватность, и любая «умная» оптимизация.
