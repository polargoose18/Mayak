# Список целей

Агент «Маяка» проверяет только цели из подписанного списка. Произвольные цели из аргументов он не принимает.

## Формат

Подписанный файл — JSON-документ `{"payload": "<base64 точных байт JSON>", "sig": "<base64 ed25519>"}`. Подпись считается над байтами payload как они есть. Образец: [targets.example.json](targets.example.json); тот же payload в читаемом виде: [targets.example.payload.json](targets.example.payload.json). Цели в образце вымышленные, подпись в нём не настоящая.

Сам список (payload) содержит `v` (версия формата), `rev` (`ГГГГ-ММ-ДД.N`, только растёт), `expires` (срок действия, не дальше 30 дней от подписи) и `items`. Подробности: [docs/KEYS.md](../docs/KEYS.md).

Поля цели:

| Поле | Что это |
| --- | --- |
| `id` | Уникальный в списке идентификатор |
| `host` | DNS-имя: ASCII, нижний регистр, не меньше двух меток, например `example.org`. Юникод только в punycode (`xn--`). Нельзя: IP-адреса, порт, путь, `*`, `@`, схему, точку в конце, внутренние зоны (`localhost`, `.local`, `.internal`, `.lan`, `.home.arpa`, `.test`, `.invalid`) и дубликаты |
| `category` | Одна из: `ai`, `video`, `messenger`, `dev`, `social`, `infra` |
| `rationale` | Обоснование, не короче 20 символов |
| `rev` | Ревизия, в которой цель добавлена или изменена |

Подпись считает владелец проекта инструментом `cmd/mayak-sign`; приватный ключ в репозитории не хранится (см. [docs/KEYS.md](../docs/KEYS.md)). Подписывается каноническая форма `payload` (компактный JSON, порядок полей как в таблице выше), как описано в `internal/targets/sign.go`.

## Как предложить новую цель

1. Откройте pull request с добавлением цели в список. Подпись в PR не нужна, список подписывает владелец при выпуске.
2. Заполните `rationale`: зачем эта цель нужна карте. Поле обязательно, PR без него не принимается.
3. Цель должна быть **публичным сервисом с массовой аудиторией**: им пользуются многие люди, и его доступность важна сама по себе. Личные сайты, закрытые сервисы и всё, что нужно только узкой группе, не подходят.
4. Проверяться будет только доступность хоста. Не предлагайте цели, к которым нельзя безопасно обращаться автоматически.
