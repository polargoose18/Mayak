# ADR-000: Положение «Маяка» относительно OONI

**Status:** Accepted
**Date:** 2026-10-13
**Deciders:** владелец проекта (решение принято 2026-10-13)

## Context

OONI уже измеряет цензуру (Probe, test helpers, открытые данные) и разрабатывает анонимные учётные данные: черновик спецификации `bk-006-anon-creds` (версия 2025.06.02, статус draft) и репозиторий `ooni/userauth` (Rust, крейты `ooniauth-core` и `ooniauth-py`, ссылка на статью eprint 2026/794). Задача «Маяка» пересекается с OONI: измерить, что и как блокируется.

На что рассчитывает «Маяк» как на отличие:

- тесты под реальные способы фильтрации в РФ: заморозка соединения после первых килобайт, троттлинг, режим белых списков;
- статус по паре «оператор × сервис» почти в реальном времени;
- бот и экспорт для авторов инструментов;
- собственная лёгкая инфраструктура, которую можно развернуть одной командой.

Сведения о составе движка `probe-cli` (Go, `web_connectivity`, `tlsmiddlebox`, test helpers) взяты из внешнего ревью и не проверялись.

## Decision

«Маяк» — самостоятельный проект с собственным тонким движком измерений (тесты из раздела 5 SPEC). Движок OONI не подключается как библиотека.

Отдельно действует правило: **криптографию не пишем сами.** Для учётных данных (ADR-005) используется чужая проверенная реализация, а не своя.

Формат отчёта «Маяка» проектируется так, чтобы его можно было конвертировать в формат измерений OONI. Отправка данных в OONI возможна позже, но требует согласования формата и того, что их приёмный сервис принимает сторонние данные. Это нужно выяснить у них, обещать заранее нельзя.

## Options Considered

### Option A: самостоятельный проект (выбран)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Средняя: пять тестов и классификатор пишутся быстро |
| Cost | Низкая стоимость старта, постоянная стоимость поддержки тестов |
| Control | Полный: форматы, сроки, приоритеты |
| Team familiarity | Высокая: каждая строка агента понятна автору |

**Pros:** скорость, фокус на РФ, свободный формат, лучше для обучения. **Cons:** повторяем часть чужой работы.

### Option B: надстройка над движком OONI
| Dimension | Assessment |
|-----------|------------|
| Complexity | Средняя: нужно изучить чужой код и его API |
| Cost | Меньше собственного кода тестов |
| Control | Зависим от решений и темпа OONI |
| Team familiarity | Низкая |

**Pros:** проверенные тесты. **Cons:** в Go пакеты в каталогах `internal/` нельзя импортировать из чужих модулей, а такие проекты ими обычно богаты (проверить); тянется их модель данных и классификация; нужно сверить лицензию с вашей; тесты под РФ всё равно писать самим.

### Option C: вклад в OONI и отдельный РФ-фронтенд
| Dimension | Assessment |
|-----------|------------|
| Complexity | Высокая: согласования и чужой процесс |
| Cost | Время на коммуникацию |
| Control | Минимальный |
| Team familiarity | Низкая |

**Pros:** общая аудитория и данные. **Cons:** самый медленный путь.

## Trade-off Analysis

Сами измерения (DNS-запрос, TCP-соединение, TLS-рукопожатие с заданным SNI) делаются стандартной библиотекой Go. Сложна классификация «почему не открылось», а она у «Маяка» специфична. Поэтому выигрыш от чужого движка мал, а цена зависимости заметна. В криптографии наоборот: ошибка стоит дорого, поэтому там берём чужое.

## Consequences

- Проще: быстро собрать вертикальный срез и показать данные; полный контроль над форматом.
- Сложнее: доказывать, зачем нужен ещё один измеритель.
- Пересмотреть: после первых 50 проб, или если появится партнёр из OONI.
