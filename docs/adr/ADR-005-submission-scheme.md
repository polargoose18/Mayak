# ADR-005: Схема отправки отчётов: Privacy Pass на запуске, OHTTP и KVAC позже

**Status:** Accepted
**Date:** 2026-10-13
**Deciders:** владелец проекта (решение принято 2026-10-13)

## Context

Нужно, чтобы спам и ложные отчёты стоили дорого, чтобы отчёты нельзя было связать с учётной записью выдачи, а в дальнейшем и с IP, и чтобы вес источника мог зависеть от его «возраста» без деанонимизации.

Что подтверждено первоисточником (`bk-006-anon-creds`, draft 2025.06.02): учётная запись с атрибутами `nym_id`, `age`, `measurement_count`; псевдоним `NYM = PRF(nym_id, nym_scope)` с областью `ooni.org/{cc}/{asn}`; при каждой отправке клиент доказывает в нулевом разглашении, что `NYM` вычислен верно, а `age` и `measurement_count` лежат в допустимых диапазонах; сервер выдаёт обновлённую запись; есть чёрный список псевдонимов и обновление ключей через `update/credential`. Реализация: Rust, `ooniauth-core`, привязки для Python (`ooniauth-py`). Привязок для Go в репозитории нет.

ZK доказывает, что отправитель — действующая, не забаненная проба нужного возраста, которая голосует один раз. Правдивость отчёта он не доказывает, и принадлежность к ASN тоже.

Ограничение проекта: сейчас единственный оператор — владелец. Второго оператора для релея нет.

## Decision

Поэтапная схема. **Запуск происходит на Privacy Pass.** Учётные данные (KVAC) и OHTTP откладываются и вводятся по необходимости.

**Этап запуска (M2–M6):**

1. Обычный HTTPS (Caddy без логов адресов). Шлюз сам определяет ASN и страну по IP соединения, вычисляет `src_bucket = H(salt_day ‖ prefix)` и сразу забывает IP. Соль меняется каждые сутки и стирается через 48 часов.
2. Privacy Pass (RFC 9576–9578) на `cloudflare/circl`: токены несвязываемы с выдачей и ограничивают частоту отправки. Защита выдачи: PoW и лимит по префиксу.
3. Вес источника: `w = w_source(cli: 1.0, web: 0.3)`. Потолок вклада одного `src_bucket` 20% веса окна, как в разделе 9 SPEC. Возраста и счётчика в весе нет.
4. Веб-проба попадает в агрегат только после появления токенов (M4.5).

**Отложено до появления условий:**

5. **OHTTP (RFC 9458)**: только когда релей держит другой оператор. Без этого он усложняет систему и ничего не даёт. С его появлением `src_bucket` на отправке заменяется подписанным заголовком релея `{asn, cc, epoch}`; `src_bucket` остаётся только на регистрации.
6. **KVAC на `ooniauth-core` (M7)**, если понадобятся веса по возрасту и честный счёт независимых источников. Область псевдонима: `asn ‖ target ‖ window`, окно один час. Нуллификатор `N = PRF(nym_id, scope)` хранится два окна. Срок жизни записи 30 дней, корзины возраста пересчитываются под него (например `<1д`, `1–7д`, `7–21д`, `>21д`). Продление записи не должно обнулять возраст, иначе теряется защита от «спящих» сибилов. Бана в стиле OONI нет: он потребовал бы долгоживущего псевдонима.
7. Rust допустим, но изолированно: вспомогательный бинарник `mayak-zk` на агенте (подпроцесс, без cgo) и контейнер `mayak-auth` на шлюзе. Окончательное решение по прототипу: размер, сборка под ARM и OpenWrt. Если не получится, остаёмся на Privacy Pass.
8. `cred_v` в манифесте; формат отчёта от схемы учётных данных не зависит.

Начальные веса на M7 (настраиваются на симуляции):

```
w = w_source(cli|web) * f_age(bucket) * g_count(bucket)
f_age   = {<1d: 0.3, 1-7d: 0.6, 7-21d: 0.9, >21d: 1.0}
g_count = {<10: 0.7, 10-100: 0.9, >100: 1.0}
квота: вклад корзины <1d не больше 30% веса окна
```

Вес никогда не растёт за «согласие с большинством».

## Options Considered

### Option A: PoW и `src_bucket` (SPEC v0.1)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Низкая |
| Cost | Низкая |
| Privacy | Сервер видит IP; обещание «забываем» не проверяется |
| Sybil resistance | Слабая |

### Option B: Privacy Pass (выбран для запуска)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Средняя, есть Go-реализация |
| Cost | Невысокая |
| Privacy | Хорошая: токены несвязываемы |
| Sybil resistance | Ограничение частоты есть, возраста и счётчика нет |

### Option C: лесенка когорт на слепых подписях
Отклонён: обмен токенов связывает цепочку, группа анонимности равна «когорта × ASN», в малых ASN единицы участников; подсчёт независимых источников невозможен.

### Option D: KVAC по схеме OONI (`ooniauth-core`) (запасной путь, M7)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Высокая интеграция (Rust в Go-проекте) |
| Cost | Готовый дизайн, статья и бенчмарки |
| Privacy | Хорошая; область псевдонима задаёт степень связываемости |
| Sybil resistance | Нуллификаторы, корзины, срок жизни, приглашения |

### Option E: собственная KVAC на Go
Отклонён: своя криптография без аудита — главный риск проекта.

### Option F: BBS-подписи и доказательства диапазона
Отложен: зрелость Go-библиотек под вопросом.

## Trade-off Analysis

Privacy Pass закрывает главное для запуска: спам и ограничение частоты без связывания с выдачей. Он не даёт возраста и нуллификаторов, поэтому «один голос на окно» не обеспечен криптографически, а независимые источники считаются по `src_bucket`, который связывает отчёты одной подсети в пределах суток. Это то же, что обещал SPEC v0.1, и это честно записывается в README. Усиление (OHTTP, KVAC) не переписывает формат отчёта.

## Consequences

- Проще: запуск без Rust и без второго оператора; `circl` на Go.
- Сложнее: нет возраста в весе; независимые источники считаются приблизительно; приватность на этапе запуска держится на политике оператора.
- Пересмотреть: при появлении второго оператора (OHTTP), при росте сибил-атак (M7), при изменении черновика OONI.
