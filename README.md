# Маяк

Открытая карта сетевой доступности.

Маяк отвечает на вопрос «у меня одного не открывается сервис или у всего моего оператора, и по какой причине?». Агент измеряет, что именно мешает открыться сервису (DNS, IP, SNI, QUIC), а сервер по желанию пользователя будет собирать обезличенные отчёты и показывать статус по паре «оператор × сервис».

Техническое задание: [docs/SPEC.md](docs/SPEC.md). Принятые решения: [docs/adr/](docs/adr/).

## Статус: альфа

Проект в разработке, пользоваться им как сервисом пока нельзя.

Есть:

- формат отчёта `mayak.report/1`, JSON Schema и валидатор (`internal/report`, `schema/`);
- пробы `dns`, `tcp`, `tls_sni`, `http` и `ctrl` и классификатор вердиктов (`internal/probe`, `internal/classify`), проверенные на мок-цензоре (`testbed/mockdpi`);
- подписанный список целей: формат v2, подпись ed25519, срок действия, защита от отката (`internal/targets`);
- инструмент владельца `mayak-sign` для ключей и подписи списка (`cmd/mayak-sign`).

Ещё нет:

- команды `mayak check`: пока `mayak` умеет только `version`;
- оркестратора с потолками нагрузки (не больше 4 одновременных проверок, пауза 200–800 мс, таймаут 8 секунд на тест): они записаны в требованиях, но в коде не реализованы;
- проб `quic`, `tcp_freeze`, `throughput`; для вердиктов `freeze_after_n` и `throttled` правил классификации пока нет;
- сервера (`mayakd`), контрольного узла (`mayak-ctrl`), согласия на отправку, публичной страницы, бота;
- подписанных релизов.

Агент сейчас ничего не отправляет и отправлять не умеет.

## Чего проект не делает

- Не обходит блокировки и не учит их обходить: Маяк только измеряет.
- Не проверяет произвольные сайты по запросу: агент ходит только по целям из подписанного списка, у каждой цели записано обоснование, цель должна быть публичным сервисом с массовой аудиторией.
- Не собирает данные о людях и их трафике: в отчёте нет IP-адреса и идентификатора установки.
- Не ранжирует операторов на «хороших» и «плохих».

## Список целей и ключ подписи

Цели лежат в `targets/`. Файл `targets/targets.json` содержит сам список, `targets/targets.signed.json` его подписанная версия. Агент принимает только список, подписанный ключом, который вшит в код (`internal/targets/pubkeys.go`). Список действует не больше 30 дней и поэтому периодически переподписывается; версия списка (`rev`) только растёт, чтобы старый подписанный список нельзя было подставить вместо нового.

Подпись ставит владелец проекта. Правила хранения ключа, смены ключа и действий при его утечке описаны в [docs/KEYS.md](docs/KEYS.md). Как предложить новую цель: [targets/README.md](targets/README.md).

## Чем Маяк отличается от OONI

[OONI](https://ooni.org) уже измеряет цензуру и публикует открытые данные. Маяк самостоятельный проект с собственным тонким движком измерений; движок OONI не подключается как библиотека ([ADR-000](docs/adr/ADR-000-mayak-vs-ooni.md)).

На что Маяк рассчитывает как на отличие (пока это цели, а не готовые функции):

- тесты под способы фильтрации, которые встречаются в РФ: заморозка соединения после первых килобайт, троттлинг, режим белых списков;
- статус по паре «оператор × сервис» почти в реальном времени;
- бот и экспорт для авторов инструментов;
- лёгкая инфраструктура, которую можно развернуть одной командой.

Если вам нужны уже собранные данные, смотрите OONI: у Маяка собственных данных пока нет. Формат отчёта Маяка проектируется так, чтобы его можно было преобразовать в формат OONI. Отправка данных в OONI возможна позже, но её нужно согласовывать с OONI, и заранее мы её не обещаем.

## Что мы обещаем и чего нет

Сейчас сервера нет и ничего не отправляется. Ниже то, что проект обещает на этапе запуска, когда появится сервер ([ADR-004](docs/adr/ADR-004-anonymity-threat-model.md), [ADR-005](docs/adr/ADR-005-submission-scheme.md)).

Обещаем:

- в отчёте, в базе и в логах нет IP-адреса; шлюз видит IP на время приёма и не сохраняет его;
- в отчёте нет идентификатора установки; `report_id` случаен для каждого отчёта, связать два отчёта по нему нельзя;
- отправка выключена по умолчанию и происходит только после явного согласия, с показом точного JSON;
- открытый код и подписанный список целей;
- ячейка «оператор × сервис» публикуется, только если данные пришли не меньше чем от пяти разных источников.

Не обещаем:

- Приватность на запуске держится на политике оператора, открытом коде и тестах «IP не оседает», а не на криптографии. Проверить извне, что сервер не начнёт незаметно логировать адреса, нельзя: шлюз видит IP на время приёма, а все компоненты держит один оператор.
- Провайдер пользователя видит сам факт соединения с сервером Маяка. Мы снижаем это (отправка со случайной задержкой от 0 до 15 минут), но не скрываем.
- Контрольный узел видит IP проб и SNI проверок.
- Анонимные учётные данные (отчёты разных окон нельзя связать, один голос на окно) и OHTTP появятся позже и по необходимости; на запуске их нет.
- Защиты от глобального пассивного наблюдателя нет. Нельзя исключить, что кто-то накопит много проб деньгами и временем.
- Агрегаты малых операторов могут раскрывать больше, чем хотелось бы; поэтому ячейка публикуется только при не менее чем пяти разных источниках, а при нехватке данных статус честно показывает «мало данных».

## Сборка и проверка

Нужен Go версии из `go.mod`.

```
make check          # gofmt, go vet, go test
make sign-check     # подпись targets/targets.signed.json
make release-check  # падает, пока в pubkeys.go есть тестовый ключ
go run ./cmd/mayak version
```

## Структура

```
cmd/mayak/          агент (пока только version)
cmd/mayak-sign/     ключи и подпись списка целей
internal/probe/     пробы dns, tcp, tls_sni, http, ctrl
internal/classify/  правила вердиктов
internal/report/    формат отчёта и валидатор
internal/targets/   подписанный список целей
targets/            список целей и обоснования
schema/             JSON Schema отчёта
testbed/mockdpi/    мок-цензор для тестов
docs/               ТЗ, ADR, правила ключей
```

Мок-цензор не умеет настоящего отбрасывания SYN без firewall: проба connect без ответа на SYN в тестах заменена истёкшим дедлайном.
